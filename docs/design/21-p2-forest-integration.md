# 21. P2 霧語森林整合：實作草案（第 13 輪，待 Jacky 選方案）

> 依據：design/20 §B（無縫戰鬥、五關放進一張森林、手機視野、死亡與恢復、掉落、UI）、D-063、D-065、D-066～D-069。
> 目的：Jacky 回覆試玩問題後，下一輪可以直接開工。**這份只是草案，標 ⭐ 的是開發迴圈的建議；Jacky 沒意見就照建議做。**

## 0. 現況（第 13 輪）
- 戰鬥核心 `src/core/battle/rt/`：純 TS、30 ticks/秒、整數座標（1 單位＝100）、`BattleState` 一場一個、**場地只有矩形外牆、沒有障礙物**、敵人一開始就全部進戰鬥。
- 探索 `src/core/explore/`：ASCII 地塊（每格 48px）、`WALKABLE` 表、A* 尋路、明雷敵人（碰到就切去舊戰鬥場景）。現有霧角森林只有 22×32 格。
- 試玩場景 `RtBattleScene`：鏡頭約 10.5 單位寬、Q 版立繪、預告、刀光、選單。

## 1. 要決定的四件事

### Q1. 地圖上的戰鬥怎麼跑？
| 方案 | 做法 | 好處 | 壞處 |
|---|---|---|---|
| ⭐ A. 整張地圖一個 `BattleState` | 把 rt 引擎擴充成「世界模擬」：加地塊碰撞、`SpawnGroup`、怪物狀態（沉睡→待機→戰鬥→返回）；遠處沉睡的怪不跑 AI | 真正無縫（RO 式）、可以邊打邊拉怪、模擬器能直接跑「刷一圈森林」 | 引擎改動最多（碰撞、狀態機、效能上限） |
| B. 遇敵時開「區域戰鬥泡泡」 | 地圖上照舊走路；碰到怪群就以玩家為中心開一個 14×18 的 `BattleState`，泡泡外的世界暫停 | 改動最少、現有 5 關幾乎直接沿用 | 不是真的無縫（拉怪、跑走都受限），和 D-063「在地圖上直接打」有落差 |
| C. A 的簡化版 | 世界由畫面層管理（Phaser 物件），怪物進仇恨範圍後才「加入」共用的 `BattleState` | 中間值 | 世界狀態一半在 Phaser、一半在核心，**不能無畫面模擬**、存檔與重現都難 |

建議 A：D-062 要求「純 TS、可無畫面模擬」，C 違反；B 和 D-063 的「在探索地圖上直接打」不一致。A 的工作量用分步驟控制（見 §3）。

### Q2. 地圖要新做還是沿用？
- ⭐ **新做一張「霧語森林」**，用現有 ASCII 地塊格式（1 格＝1 戰鬥單位＝畫面約 68px），**原型尺寸約 48×96 格**（design/20 寫 120×120，但原型先小一點，內容密度比較好；之後再擴）。路線：南邊入口（營火）→ 森林入口 → 分岔（狼群巢穴／森林深處，深處有第二個營火）→ 精英狼群 → 北邊狼王巢穴。
- 替代：把現有霧角森林（22×32）＋狼徑拼起來——太小，放不下五個區域與分岔。

### Q3. 新舊主線怎麼並存？
- ⭐ **標題畫面加一個入口「即時戰鬥原型：霧語森林」**，舊主線（回合制＋同伴＋劇情）照舊能從頭玩到結局，直到 P5 驗收後由 Jacky 決定何時下架舊戰鬥。原型用獨立存檔欄位，不碰舊存檔。
- 替代：直接把新森林接進第 1 章取代舊戰鬥——主線其他章節還是舊戰鬥，體驗會斷層。

### Q4. 操作
- ⭐ 照 design/20 B3：點地移動（A* 尋路）、點敵鎖定、搖桿一動就取消路徑；鏡頭 12～14 單位寬（比試玩場景 10.5 稍遠，因為地圖上要看路）、Boss 戰拉遠。右下：技能 1～4＋閃避＋**藥水**＋**大招**（P2 開始放鍵位，D-068／D-069）。

## 2. 方案 A 的資料草案
```ts
// src/core/battle/rt/world.ts（新）
interface SpawnGroup {
  id: string; cx: number; cy: number; spawnRadius: number;
  enemyId: string; maxAlive: number; respawnTicks: number;
  tier: 'normal' | 'elite' | 'boss';      // 決定仇恨半徑／追擊距離／脫戰等待（design/20 B1 表）
}
type EnemyMode = 'dormant' | 'idle' | 'combat' | 'returning';
interface WorldState extends BattleState {
  grid: { w: number; h: number; walk: Uint8Array };   // 從 ASCII 地塊轉換
  groups: SpawnGroup[]; respawnAt: Record<string, number[]>;
  modes: Record<number, EnemyMode>; home: Record<number, { x: number; y: number }>;
  lastCombatTick: number;                              // 自然恢復：脫戰 5 秒後每秒 2%
  campfires: { id: string; x: number; y: number }[];
}
```
- **碰撞**：圓形對地塊（只檢查周圍 3×3 格），沿牆滑動；衝鋒撞到不可走地塊＝撞牆（沿用 `wallStun`）。
- **仇恨**：距離＋視線（格子直線檢查，不隔牆吸怪）；同時追擊上限 8、進戰鬥 AI 上限 12（超過的排隊）。
- **沉睡**：離玩家超過可視範圍 2 倍的怪不跑 AI、不檢查碰撞（效能）。
- **脫戰**：超過最大追擊或等待時間 → `returning`（回滿 HP、清狀態），Boss 則重置整場。
- **狼王**：不重生；離開巢穴區域再進來就重置；首殺記旗標。
- **確定性**：沿用 `rngState`、固定處理順序（沉睡判定 → 輸入 → 玩家 → 戰鬥中敵人 id 順序 → …）；`stateHash` 加入怪物模式與重生計時。

## 3. 建議的開工順序（每步都要能玩、能測）
1. **地塊碰撞**：`BattleState` 可選 `grid`；五個原型關卡加幾顆石頭測試；現有測試全綠、1,000 次一致。
2. **SpawnGroup＋怪物模式**：沉睡／待機／戰鬥／返回、仇恨半徑、最大追擊、脫戰回滿；重生計時。測試：拉怪到極限會回家、重生時間正確。
3. **霧語森林 ASCII 地圖**＋`ForestScene`（沿用 `RtBattleScene` 的畫面層：立繪、預告、刀光、HUD），點地尋路＋搖桿。
4. **營火、自然恢復、死亡回營火**（不掉裝、不扣經驗）、藥水與大招鍵位。
5. **模擬器：Bot 從營火出發刷一圈森林**（地圖版 `batch`），量清一區時間、藥水消耗、死亡率。
6. 之後才是 P3（Boss 細節在地圖上的版本）與 P4（地面掉落、自動撿取、背包 60 格）。

## 4. 不做（P2 範圍外）
狼群暴動事件、小地圖、任務追蹤、高等區警告、地面掉落與背包（P4）、多張地圖、NPC 對話（森林裡只留營火與出入口）。
