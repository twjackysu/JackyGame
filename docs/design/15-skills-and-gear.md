## 0. 共通規則（技能樹與裝備共用）
### 0.1 效果框架
所有效果 = **觸發事件 → 條件 → 效果 → 上限**。事件（只有這 12 個）：`OnAttack`、`OnCritical`（＝完美判定）、`OnBlock`、`OnPerfectBlock`、`OnDodge`、`OnMarkCreated`、`OnResonance`、`OnEnemyKilled`、`OnBreak`、`OnTurnStart`、`OnDamaged`、`OnAllyDown`。
效果種類（`EffectKind`）：`TriggerEffect`（事件觸發）、`ActionModifier`（修改既有技能的參數，如成本、倍率、燈印上限）、`PassiveModifier`（修改角色或戰鬥屬性）。三者共用同一張 `NodeEffect` 資料表與條件判斷器。
內建操作（有限、由引擎保證一致性，資料表只決定何時、對誰、參數）：`CreateMark`、`MoveMark`（既有燈印的原子轉移，不是新種類）、`ConsumeMarks`、`ApplyStatus`、`RemoveStatus`、`ModifyDamage`、`ModifyResource`（SP／星燼）、`Heal`、`RewindLastEnemyAction`。
**不發明新資源、新畫面、新燈印種類。**

### 0.2 防無限循環（最重要）
- 效果有來源：`Natural`（玩家原始操作或敵人正常行動）／`Equipment`／`SetBonus`／`SkillTree`。**衍生事件預設不再觸發任何裝備或節點效果**：額外放置的燈印不觸發 `OnMarkCreated`、額外共鳴不觸發 `OnResonance`、額外傷害不觸發 `OnAttack／OnCritical／OnEnemyKilled`、燈印轉移不觸發 `OnMarkCreated`、復活不觸發 `OnAllyDown`。
- 每個效果必須有 `TriggerLimit` ＋ `TriggerLimitScope`（`Action`／`Round`／`Battle`）＋ `TriggerLimitOwner`（`Source`／`Target`／`Team`）。多目標攻擊要有 `OncePerAction`，避免打 5 隻觸發 5 次。
- 同一事件的多個效果依 `Priority` 固定結算；結算順序：原始事件 → 傷害修改 → 資源／狀態 → 衍生事件。
- 事件上下文必須保存 `引爆前燈數`（`OnResonance` 要用）、來源角色、目標、技能、是否自然事件、原始與最終傷害、是否破防。
- 不要讓 JSON 執行任意程式；條件只用**欄位與運算子白名單**：`SourceCharacterId／TargetCharacterId／SkillId／SkillTags／IsPerfect／TargetMarkCount／TargetHasStatus／TargetIsBroken／SourceHPPercent／TargetHPPercent／EnemyCount`，`AND／OR`，`EQ／GTE／LTE`。

### 0.3 傷害乘區（兩段建議整合，**數值上限待模擬校準**）
`D = ATK × 技能倍率 × 時機 × 弱點 × 破防 × (1 + DamageBonus) × 40/(40+DEF)`
- 時機（完美 1.5／良好 1.15／失誤 0.85）、弱點（1.5／0.5）、破防（1.5）各自獨立乘區。
- **DamageBonus 加算池**：技能樹一般傷害加成、裝備傷害加成、共鳴專屬加成、完美專屬加成全部**加算**進同一池。**已拍板：單一池，上限先設 +150%（D-056），用模擬器校準。**
- 取捨類懲罰（例：快速引爆 ×0.75）**獨立乘算**，不進加算池，玩家才無法用其他加成抵消。
- 燈印灼傷：`n × 0.15 × ATK × BurnModifier × Defense`；不吃時機、弱點、破防倍率，不觸發 `OnAttack／OnCritical`；`BurnModifier` 上限 +100%。
- 範例（為何要加算）：共鳴 3.2×ATK，若完美 1.5、弱點 1.5、破防 1.5、超載 1.4 全連乘 = 15.12×ATK；改加算後有上限，才好平衡。

### 0.4 星燼統一規則
- 基本來源：完美攻擊 +1、擊中弱點 +1（每次**主動行動**這兩者合計最多 +1）；**造成破防 +2 為特例**（原規則「每次行動最多 +1」與「破防 +2」互相衝突，採此特例）；同一範圍攻擊破防 3 隻也只 +2。
- 反應來源：完美格擋、完美閃避，**每角色每輪合計最多 +1**。
- 技能樹／裝備直接返還：不受上述 +1／+2 限制，但各有觸發上限，被動額外傷害不再產生星燼，全隊上限 10。
- 結算順序：技能消耗 → 執行攻擊 → 時機判定 → 傷害與破防 → 基本星燼獎勵 → 被動 → 擊殺返還 → 套用上限 10。所有資源增減走統一的 `ResourceService`，不可直接改數值。

### 0.5 倒帶（回溯）規格
- 回溯只撤銷「敵人最近一次已完成行動」造成的 **HP 傷害與負面狀態**；**不回復 SP、星燼、冷卻、燈印，不撤銷敵人死亡，不重置每場一次紀錄，敵人不會重新行動**。需要戰鬥快照（目前引擎已有 `rewindSnapshot`，記錄全隊 HP、倒地、中毒、蝕化）。
- 神級／傳說的「對單一隊友倒帶」需要「只還原該隊友」的快照版本（現有快照是全隊）。

## 1. 技能樹 v3
### 1.1 設計論點
技能決定「能做什麼」，技能樹決定「何時、為何、以什麼順序用」：把技能樹從「角色數值成長」改成**「戰鬥規則改造」**。現有樹幾乎全是 +N%，沒有選擇感；裝備負責數值，技能樹負責玩法。
**節點分類比例**：數值 15%、規則 30%、連動 25%、取捨 20%、里程碑 10%。
**取捨**：局部互斥（同分支兩個節點二選一）＋終極互斥（連恩三條分支的終極技能全域只能選一個）；同伴每人只能啟用一個終極。免費重置。
**技能點**：等級上限 20，每級 1 點，Boss 首殺全體各 +1（現有 5 隻首殺，建議 6 隻）；一般節點 1 點，終極 2 點。選定終極流派後，**其他分支只能解鎖至第四層，不能取得其他分支的里程碑**。
**分支解鎖**：第二層需該分支已投入 ≥1、第三層 ≥3、第四層 ≥5、第五層 ≥7；連恩終極節點需該分支 ≥8（計算「點選當下、尚未含此節點」的投入）。
**需要自動驗證器 `ValidateSkillTree()`**：前置 id 存在、無循環、每個節點都有合法路徑、互斥不造成無法解鎖、終極可在點數上限內取得、每角色最多啟用一個終極。

### 1.6 技能樹資料表
`SkillNode`（Id、CharacterId、BranchId、Name、Description、NodeType、Tier、PointCost、PrerequisiteIds、PrerequisiteMode ALL／ANY、RequiredBranchPoints、ExclusiveGroupId、UnlockSkillId、IsEnabled、SortOrder）。**終極互斥與局部互斥用同一個 `ExclusiveGroupId`**（例：`LIAN_B5_B6`、`LIAN_ULTIMATE`），不需要另一個欄位。
`NodeEffect`（Id、NodeId、EffectKind、Trigger、Condition JSON、EffectType、TargetSelector、TargetSkillId、Property、Operation Add／Multiply／Override、Value、Duration、Priority、**TriggerLimit／TriggerLimitScope／TriggerLimitOwner**、CanTriggerOtherEffects、SourceFilter、OncePerAction、StackGroup、EffectTags、IsEnabled）。
`SkillDefinition`（Id、CharacterId、Name、SPCost、EmberCost、TargetType、DamageMultiplier、BreakPower、CooldownTurns、UsageLimitPerBattle、Tags、EffectIds、UnlockLevel、UnlockNodeId、IsDefaultUnlocked）。
`SkillSlot`（BuildId、CharacterId、SlotIndex 0–3、SkillId、IsLocked；唯一鍵 BuildId＋CharacterId＋SlotIndex，同一 Build 不可重複技能）。
`PlayerBuild`（Id、CharacterId、Name、AllocatedNodeIds、TotalSkillPoints、UsedSkillPoints（只當快取，載入時由節點成本重算）、IsActive、Version、UpdatedAt）。
`ModifierResolver` 順序：Base → Add → Multiply → Override → Clamp；每個屬性可有自己的規則（例：成本最低 1）。技能修改器必須有固定順序，點選順序不能影響結果。
範例列（B5 超載引爆）：`{"Id":"LIAN_B5","NodeType":"Tradeoff","Tier":4,"PointCost":1,"PrerequisiteIds":["LIAN_B4"],"RequiredBranchPoints":5,"ExclusiveGroupId":"LIAN_B5_B6"}`＋兩筆 `ActionModifier`：`EmberCost` Override 5、`SkillTreeDamageBonus` Add 0.4（目標技能 `RESONANCE`）。

### 1.8 引擎能力與里程碑
優先：`SkillDefinition` → `BattleEventContext` → `ConditionEvaluator` → `EffectExecutor` → `ModifierResolver` → `ResourceService` → `TriggerLimiter` → `StatusManager` → `MarkManager`（放置、轉移、消耗、保留）→ `SkillTreeValidator` → `SkillSlotManager` → `BattleSimulator` → `BattleSnapshot`。
M1 `SkillDefinition＋ModifierResolver`（B5／B6 正確）→ M2 事件＋執行器（G2 完美格擋放燈印）→ M3 條件＋觸發限制（同事件不重複拿資源）→ M4 狀態＋燈印管理（S9 正確）→ M5 20 節點 MVP（三流派都能打完同一隻 Boss）→ M6 驗證器＋槽位管理＋免費重置 → M7 模擬器 → M8 完整樹。
