# 14 實作順序（長尾刷寶、強化、戀愛線、可移植後端層）

> 依據：`13-chatgpt-ideas.md`（題目 1b、2、3）與 `DECISIONS.md` D-053、D-054。Jacky 10/24 同意照此順序。
> **每一階段結束時遊戲都要能玩、`npm test` 與 `tsc` 全綠、通關機器人（auto-build）仍能全程通過。** 沒完成上一階段的驗收，不要開始下一階段。

## 原則
1. **先打地基，再蓋內容。** 最大的風險是裝備資料結構與亂數，晚改會牽動全部。
2. **權威邏輯放 `src/server/`**（見其 README 與 `tests/server-boundary.test.ts`）；前端只呼叫它、不重算。
3. **每個新系統都要有模擬測試**（`src/core/battle/sim.ts` 一路擴充）：看分布（P50／P90／P99），不只看平均。
4. 數值與機率放資料表，並帶 `rulesVersion`；玩家看得到成功率與失敗後果。
5. 不覆蓋既有劇本與約會事件（D-051 的 `dates.ts`）；戀愛線是在上面擴充。

## 給開發迴圈的規則
- 任何改變玩家資產（金幣、材料、裝備、祝福值）的新程式，**一律寫在 `src/server/`** 並經 `GameApi` 呼叫；場景裡不得直接改狀態。
- `src/server/**` 不得使用 `Math.random`、`Date.now`、瀏覽器全域；違反會讓 `tests/server-boundary.test.ts` 紅燈，**不要為了讓測試綠燈而放寬測試**。
- 動到存檔格式必須同時提供 migration 與測試；不要破壞舊存檔。
- 不要在階段 1 完成前開始階段 2 以後的內容。
