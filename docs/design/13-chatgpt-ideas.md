## 題目 1：怎麼留住玩家（2026-10-24）
對話：<https://chatgpt.com/c/6adc982b-a324-83ee-8061-26825af104cd>

### 核心論點
- 最大賣點不是戰鬥、裝備或戀愛，而是設定本身：**「我知道劇本，但越想改變命運，攻略就越失準」**。所有系統都該回饋這個主題（照顧瑟琳 → 解鎖救她的新方法；研究燼牌 → 發現筆記沒有的情報；研究燈印 → 解鎖原作沒有的解法）。
- 4 個動機循環：改寫命運（筆記、偏移值）、掌握力量（燈印、技能樹）、建立關係（羈絆、營火、約會）、探索未知（探索、燼牌、隱藏事件）。
- 主線只有約 5 小時，**不要靠刷材料、刷好感拉長時間**；目標是五小時精彩故事加通關後想推薦朋友。一週目 5h、二週目 2–3h、集齊結局合計約 10–15h。
- 系統偏多：核心循環固定為「探索 → 發現命運情報 → 做選擇 → 戰鬥或事件 → 世界變化 → 筆記更新」，其他系統服務這個循環。
- 好結局的條件不要讓玩家非查攻略不可（不要藏在「好感 ≥ 65 且偏移值 ≤ 43」這種數值後面），要轉成可調查的線索。
- 先做 30–45 分鐘垂直切片驗證，成功標準：玩完第一句話是「瑟琳到底能不能救？」。

## 題目 1b：離線單機的長尾刷寶與配裝系統（2026-10-24，簡報已更正目標）
同一個對話（續問）：<https://chatgpt.com/c/6adc982b-a324-83ee-8061-26825af104cd>
定位：**暗黑的隨機裝備 × RO 的流派構築 × 天堂的稀有掉落 × 命運偏移**。總時數目標：主線 0–5h、初期刷寶 5–10h、中期 10–15h、高階深淵 15–20h、Build 研究 20–25h、終局收藏 25–30h+。

### 刷寶為什麼上癮，離線怎麼補
六要素：隨機驚喜、角色成長、Build 研究、稀有收藏、挑戰突破、效率優化。核心循環是「刷裝 → 改 Build → 挑戰更高難度 → 刷到更好的裝 → 再改 Build」。
離線版替代「多人比較、交易」：
- **個人紀錄取代排行榜**：最高層數、最短回合、最高單次共鳴傷害、無傷通關、使用的 Build。
- **Build 圖鑑取代社群攻略**：發現新組合時攻略筆記記錄（「已發現關鍵裝備 2/4」），不一次公開最佳解。
- **收藏室取代交易價值**：傳說、神級、套裝、特殊 Boss、隱藏 Build 展示，可產生配置卡片分享（不需伺服器）。

### 核心玩法：星燼深淵（主線通關後解鎖）
- 一場 5 到 10 分鐘，5 個房間（戰鬥、事件或寶箱、精英、Boss）從模板抽取，重用現有地圖與敵人，不做大型程序生成地圖。
- 主題「失落的命運」：瑟琳死去的世界、洛克沒背叛的世界、騎士團覆滅的世界、伊歐從未被刪除的世界。
- **深淵變異詞綴**（每場抽 1–3 個）：暗潮蔓延、星燼暴走、時序錯亂、無光之夜、命運逆轉、星火祝福。
- 難度 50 層：1–10 稀有、11–20 史詩、21–30 傳說、31–40 高品質傳說、41–50 神級。50 層後無限層，但**裝備不再升級**，只給紀錄、外觀、收藏。
- 增加戰鬥規則變化（敵人交換位置、Boss 吸收燈印、禁用特定技能、反彈完美格擋），不只是加血加攻，避免無聊。

### 裝備
- **6 格**：武器、防具、頭飾、飾品 ×2、**星燼核心**（改變戰鬥機制，例如「永燃之心」：火燈印不會消失，但每回合失去 3% 生命）。
- **6 階稀有度**：普通、魔法、稀有、史詩、傳說（固定效果加隨機詞綴）、神級（固定神級效果改變核心機制）。傳說與神級要「改變玩法」，不只是數值更高；神級不全面碾壓傳說（傳說適合速刷、神級適合高難度）。
- 詞綴：混合制。普通到史詩全隨機；傳說固定特殊效果加隨機一般詞綴；神級固定神級能力加隨機次要詞綴。使用詞綴池、依裝備類型限定、互斥群組。
- 套裝只做 2 件、3 件，效果要「新玩法」而非單純加數值（例：星火守望者、失落星衛、蝕星使徒）。
- 掉落：Boss 必掉一件主裝備，稀有 45%／史詩 35%／傳說 18%／神級 2%（初始值，待測）；**軟保底**（10 場無傳說逐步加機率）、**硬保底**（40 場無神級必掉）；重複神級分解成「神格碎片」，20 個可指定製作已解鎖的神級。保底要包裝成世界觀裡的「星燼凝聚」，不要像抽卡。
- 強化：**必定成功**（不做天堂式爆裝，因為離線沒有補救），最高 +10，高階需要更多材料；詞綴重鑄可鎖定其他詞綴，成本遞增並設上限。材料控制在 5 到 7 種，所有裝備可分解。

### Build 深度
掌燈人六大流派：**星火爆發**（累積後引爆）、**永燃持續**、**完美格擋**（格擋生成燈印）、**共鳴連鎖**（共鳴後重生燈印）、**蝕星風險**（犧牲生命換傷害）、**時序控制**（伊歐倒帶）。
關鍵手法：**同一個技能在不同裝備下產生不同效果**（例如「點燃燈印」搭永燃之心不消失、搭初火之燈給共鳴能量、搭蝕星核心耗 5% 生命生成兩個），用少量技能產生大量玩法。同伴每人先做兩條流派，隊伍組合也是研究對象。

### 與劇情串連
- **偏移值決定掉落池**：低偏移出騎士團裝備、中偏移失落歷史、高偏移蝕星裝備、極高偏移「不存在的神級裝備」。**通關後深淵用獨立的「殘響偏移值」**，玩家可自由調，不必為了裝備破壞主線結局。
- **同伴專屬傳說**：瑟琳「未折之誓」（連恩低血時替他擋致命一擊）、莉歐拉「自由鍊金手札」、伊歐「遺忘的時針」（倒帶後下次共鳴不耗燈印）、洛克「老兵的最後一枚硬幣」。
- **攻略筆記記錄 Build**：流派圖鑑、已發現關鍵裝備、最高傷害、最高層數；裝備詳情會推薦「下一個目標」（套裝缺哪件、在哪個深淵取得），玩家可追蹤一個目標。
- **燼牌刻印**：擊敗特殊牌手得刻印（滿月、殘月），可裝備提供戰鬥效果；但要提供替代取得途徑，不強迫精通燼牌。

### 路線圖
| 階段 | 規模 | 重點 |
|---|---|---|
| 最小可玩版 | 4 格裝備、普通到傳說、15 件基礎裝備、20 種詞綴、6 件傳說、2 套裝、3 流派、1 種深淵、5 房間模板、2 Boss、4 變異、10 層 | **先做通用效果框架**，驗證「刷寶有沒有趣」 |

| 完整版（30h+） | 80 件基礎、80–100 詞綴、40 傳說、10–12 神級、10 套裝、5 深淵、30 房間、8–10 Boss、20–25 變異、50 層加無限、12–15 隱藏 Build | 神裝製作、個人挑戰紀錄、收藏室、二週目特殊深淵、燼牌刻印 |

資料表範例欄位：`EquipmentTemplate`（ID、Name、Slot、Rarity、BaseStats、AffixPoolID、UniqueEffectID、SetID）、`Affix`（ID、StatType、Min、Max、Weight、AllowedSlots、ExclusiveGroup）、`Dungeon`（ID、Difficulty、EnemyPoolID、BossPoolID、ModifierPoolID、LootTableID）。

### 要避免的坑（ChatGPT 的對策）
1. **數值膨脹**：裝備基礎數值有上限，50 層後不加等級，高階裝備給機制不給倍率；暴擊、冷卻縮減設上限；傷害加成多用加法。目標是終盤強 Build 比普通 Build 強數倍，而非數萬倍。
2. **Build 失衡／無限循環**：統一效果觸發系統（OnAttack、OnCritical、OnBlock、OnMarkCreated、OnResonance、OnEnemyKilled），每個效果有觸發條件、冷卻、每回合上限、是否允許連鎖；裝備效果產生的額外共鳴預設不能再次觸發同一件裝備的共鳴效果。
3. **重複變無聊**：深淵加規則變化而不只加數值。
4. **手機 UI**：三層資訊（列表只顯示名稱、稀有度、評分、特殊效果圖示；詳情顯示完整詞綴；比較模式只顯示差異）；一鍵分解低稀有度、自動鎖傳說以上、Build 預設存檔；不單靠評分判斷好壞。
5. **改存檔**：做基本完整性檢查與備份即可，離線沒有排行榜與交易，不值得投入反作弊。

### ChatGPT 的優先順序
1. **資料驅動的裝備／詞綴／效果引擎**（所有長尾內容的基礎，沒有它每新增一件特殊裝備就多一份維護成本）
2. **燈印共鳴與裝備效果的 Build 深度**（先讓 3 種流派真的好玩再擴到 6 種）
3. **可重複挑戰的星燼深淵與目標掉落**
評估指標：「玩家取得第一套完整 Build 後，會不會主動想研究第二套？」

### Claude 評註
- **同意方向**，而且它與現有架構相容：效果觸發框架可以掛在現有戰鬥事件上，`src/core/sim/` 已有戰鬥模擬器可以擴充成 Build 批次測試（這是整套系統最重要的安全網）。
- **前提差異**：ChatGPT 假設燈印有火、風、光、盾、暗、時等多種類，但目前遊戲的燈印只有一種。若採用，要先決定要不要加「燈印種類」，這會影響技能樹、敵人弱點與戰鬥 UI；建議由 Jacky 決定，或先用「同一種燈印、不同觸發效果」的方式做最小版。
- **現有設計會被改動**：裝備欄從 3 格變 6 格、`MemberState.equipment` 的資料結構、掉落與商店、存檔格式都要擴充；手機直式的裝備比較 UI 是最大的 UI 工程。
- **內容量**：完整版的數量對手工是不可能的，必須由資料表加程式規則生成（詞綴池 × 模板），再由 AI 批量產出名稱與敘述。
- **美術**：裝備圖示已有 `sheet_gear`，每件傳說以上若要獨立圖示，Gemini 額度會成為瓶頸；詞綴裝備建議用「模板圖示 + 稀有度外框與顏色」。
- 它的 2% 神級與保底數字只是起點，必須用模擬器校準。
- 它把裝備強化設計成「必成功」，我同意（離線沒有交易，爆裝只會逼玩家讀檔）。
- 提醒：保底與掉落機制若做得像抽卡手遊，可能影響「全年齡、免費、無內購」的觀感，建議保留 ChatGPT「星燼凝聚」的世界觀包裝。

主張：**這不是一款讓你攻略女主角的遊戲，而是一款讓你發現「攻略無法得到真心」的遊戲**。連恩知道原作會發生什麼、知道怎麼改變別人的命運，卻不知道被改變命運的人會不會愛上他。宣傳句建議：「我記得這個世界的所有攻略，卻不知道該怎麼讓妳喜歡我。」

### 現有設計的問題
1. **好感度只是進度條**：玩家只想刷到 100，不一定期待下次見面。建議保留好感 0–100，但**重大事件旗標（是否尊重她）才決定感情能否升到「心之所向」**，不要新增第二條「戀愛值」。送禮可提高親近，但解決不了角色的內心衝突；送禮每階段要有好感上限。
2. 「好感過低就離隊」建議改成：**可暫時疏遠，永久離隊只由重大劇情選擇觸發**，否則玩家會因不熟悉喜好而失去戰鬥夥伴。
3. 全程互動由玩家主動，角色像在等點擊的 NPC → 加**同伴主動邀約**（好感達門檻時由同伴開口，可稍後再去、拒絕不扣好感、無時限，避免 FOMO）。

### 三位角色：三種完全不同的戀愛
| | 伊歐 | 瑟琳 | 莉歐拉 |
|---|---|---|---|
| 類型 | 神祕、純愛、命運系 | 歡喜冤家、慢熱、成長系 | 日常喜劇、互相扶持 |
| 核心衝突 | 記憶與存在 | 保護與自主 | 信任與控制 |
| 玩家想保護的 | 她存在的權利 | 她選擇人生的權利 | 她自由創造的權利 |
| 招牌場景 | 井裡的星星（燈印照亮倒影、連恩這次沒有找標準答案，而是等她說） | 沉鐘礦坑死亡預言（用筆記強行阻止 vs 告訴她真相一起制定戰術；選前者會被質問「你憑什麼替我決定」，但**不會永久失去戀愛資格，之後有修復機會**）＋劍穗的顏色（選銀／藍／紅，戰鬥立繪的劍穗會換成玩家選的顏色） | 燼牌作弊事件（用筆記預測會被她吐槽，不用筆記輸了她反而開心）＋會開花的火藥（調三種材料比例，失敗也加好感、不懲罰） |
| 真正的兩難 | 地下研究院能恢復她的記憶但會增加偏移：**判斷標準是玩家有沒有先問她的意願**，不是唯一正解 | 沉鐘礦坑 A/B 選擇 | 保留或銷毀她的危險研究（銷毀／保留並加安全限制／交騎士團監管），**保留要付代價（放棄稀有材料或強力裝備）** |
| 心之所向條件 | 好感 ≥75、4 個事件、井裡的星星、至少一次尊重她對記憶的決定 | 好感 ≥75、4 個事件、劍穗的顏色、她已放下家族認可、一次真正並肩作戰 | 好感 ≥75、4 個事件、會開花的火藥、完成共同研究、支持她的研究自主 |
| 結局 | 被記住的星星（最佳）／遺忘之後（保留部分失落但有重新開始）／沒有名字的歌（友情） | 並肩的騎士（她先成為自己再同行，不為連恩放棄騎士夢）／各自的道路／未放下的徽章 | 未完成的明天（工坊終於不會爆炸，遠處傳來爆炸聲）／世界第一的鍊金術師／不再爆炸的工坊 |

### 攻略筆記與戀愛（它認為最重要的機制）
- 角色條目分兩層：**【原作情報】**（前世知道的）與**【親身記錄】**（這輪旅程真正理解的）；兩者衝突時顯示「⚠ 原作情報已失準」。筆記從「遊戲攻略」逐漸變成「連恩對同伴的理解」，旅途記錄的文字會隨羈絆階段自動替換（初期「瑟琳：第二章死亡角色」→ 終章「我希望她能實現自己的夢想」）。
- **不要懲罰使用筆記**，否則玩家只會學到「談戀愛別用筆記」，核心機制就廢了。代價落在「把答案強加在別人身上」：用筆記了解角色過去＝有幫助；預測反應＝可能被看穿；強迫事件照預期走＝偏移加關係衝突。**「事件成功、感情未必成功」**才是特色（用筆記讓瑟琳贏決鬥，檢定成功，但她不一定開心）。
- 每人一次「被看穿」事件且反應不同：伊歐難過（「你記下這些，是想讓我開心，還是把我當真人？」）、瑟琳憤怒（「那我到底還有什麼是自己決定的？」）、莉歐拉先興奮後受傷（「你每次鼓勵我，也是筆記寫著要這麼做嗎？」）。
- 終章共通事件「沒有寫下的答案」：筆記顯示「偏移值 87%，原作劇本已失效，無法預測同伴行動，是否繼續？」，三人各有不同的反應，連恩從「全成就玩家」變成這個世界的居民。

### 互動點子（成本都低到中）
雙人戰鬥連攜（每人一招，伊歐「星燈・逆時之約」、瑟琳「星燈・破曉誓劍」、莉歐拉「星燈・超新星實驗」；**戀愛不提供獨占的強力數值**，只解鎖演出與台詞，避免玩家為戰力被迫選人）、共同刷寶事件（累積場次門檻觸發，每人 3–5 句，不要求連刷）、同伴主動邀約、特殊禮物回饋、約會場景互動、戰鬥默契事件、營火隨機話題、同伴記住選擇。

### 全年齡與多人好感：「多人親密，單人承諾」
- 所有角色都能升到高好感，戀愛關係只在**終章明確選一人**才成立；好感 100 不會自動變戀愛。
- 角色之間不為「誰比較喜歡連恩」爭吵；不是所有親密互動都寫成曖昧；告白後其他角色仍是重要同伴，已明說心意者未被選中時有一段簡短成熟的回應。
- **友情結局要認真做**：命名《星燼回響：我們的旅途》，攻略筆記最後一頁不再顯示「主線完成度 100%」而是旅途記錄，結尾是「這個世界，已經不需要攻略了」＋所有同伴在營火旁重聚。

### 優先順序（只做三樣）
1. 三位角色各 **4 場核心羈絆事件**（事件 1 建立特色、2 拉近、3 核心衝突、4 解決並建立信任），共 12 場加 3 場約會，約 180 則對話；整體含告白與後日談約 20–25 場，可控。「初識」可直接用入隊事件。
2. **攻略筆記：原作情報＋親身記錄**（資料結構 `characterId／originalFacts／discoveredFacts／importantChoices`，只在角色頁加兩個分頁）。
3. **戰鬥連攜與同伴特殊反應**（每人 1 招連攜、3 句 Boss 台詞、3 句刷寶台詞、1 個禮物回應）——因為長尾核心是刷寶，戀愛要能延伸進去。

### 它警告的陷阱
好感只是數字、三位女主角都要被拯救（同質）、筆記永遠是錯的、選項都有標準答案、送禮無限刷、分支無限膨脹、戀愛影響最強裝備。

### Claude 評註（題目 2）
- **強烈同意主軸**：「事件成功、感情未必成功」與「不懲罰筆記、只懲罰強加」解決了我之前擔心的核心機制矛盾，這是整份最有價值的部分。
- 它用了 TypeScript 範例 `RelationshipState`，但**現有程式已有 `affinity` 與 `bondTier()`（`src/data/bonds.ts`）**：升階已要求「好感 ＋ 已完成事件數」，其實已經是「好感與事件分離」的一半。實作時是擴充現有旗標，不是新增資料結構。
- 約會事件現在就叫「井裡的星星」「劍穗的顏色」「會開花的火藥」（D-051），所以 ChatGPT 提的招牌場景和已寫的事件名稱重疊，**要先對照 `src/data/dialogue/dates.ts` 的現有內容再決定是改寫還是新增**，不要覆蓋。
- 它建議的「瑟琳姓氏艾斯特」與設定的「艾凡斯（Evans）」不一致；以設定為準。
- 它假設有「沉鐘礦坑破壞支柱」的劇情選項；實際第 2 章的分歧是「是否告訴瑟琳未來」，需要對照現有 ch2 劇本。
- 「離隊」要改成由劇情觸發這點需先查現有程式（有 `ch3`、`ch4` 劇本使用離隊），再決定怎麼改。

## 題目 3：衝裝備拚機率與未來連線化（2026-10-24）
對話：<https://chatgpt.com/c/6adc9bbb-d2a0-83ee-87c0-af2bebeb6375>

### 結論
- **離線版放機率強化，但不爆裝**：「讓玩家願意賭，是因為成功很令人興奮，而不是因為失敗會摧毀過去幾十小時的努力。」
- 離線和線上的差異：離線沒有交易市場來回收失敗成本、沒有社群炫耀，爆掉神裝（20 小時成果）只會讓人棄玩；所以**不能直接照搬天堂**。替代炫耀的方式：+7/+9/+10 武器光效、首次 +10 成就、裝備圖鑑記錄最高強化、深淵結算展示核心裝備、高階裝備改變戰鬥特效。

### 建議採用「A＋B＋D」，第一版不做 C
| 方案 | 內容 | 建議 |
|---|---|---|
| A 安全區＋降級風險 | +0 到 +5 必成；+6 80%（失敗保持）；+7 65%、+8 50%、+9 35%、+10 20%（失敗降 1 級，最低降到 +5）；裝備、詞綴、套裝永不消失 | 採用 |
| B 失敗累積祝福值 | 失敗累積祝福，滿了下次必成；+6 到 +8 失敗各 +20（5 次保底）、+9/+10 各 +10（10 次保底）；祝福綁裝備實例與目標階段，降級不清除 | 採用，核心保護 |
| C 玩家自選風險 | 穩定強化（100%、成本約 5 倍）或冒險強化 | **先不做**，等數值穩定再加（平衡與 UI 都複雜） |
| D 詞綴重鑄賭博 | 重鑄 1 條、鎖定 1 或 2 條後重鑄，成本遞增；**可選擇保留舊詞綴或接受新詞綴**；詞綴數值範圍公開；固定傳說效果不能被重鑄 | 採用，最適合撐長尾（強化等級有終點，詞綴組合沒有） |
- 初版資源：星幣、星燼粉塵、凝縮星燼、星之祝福（失敗補償，非付費）。成本範例：+10 要粉塵 300、凝縮 8、星幣 3,000（皆為待模擬的初值）。
- **強化加成要限制**：+10 只給裝備基礎數值約 +40%（+5 15%、+7 23%、+9 32%），不要複利，否則強化壓過 Build、詞綴與套裝。
- 要避免：爆裝、強迫強化到 +10 才能通關（主線 +0–3、深淵 1–20 層 +5、21–50 層 +5–7）、機率不透明（直接顯示成功率、失敗後果、祝福進度）、偷偷調整機率、讓讀檔變成最有效率的玩法。
- 提醒的陷阱：**保底只看單一階段會誤判**，+9→+10 失敗降回 +8 再重爬的挫折感很高，要用模擬器看 +5 到 +10 的完整成本分布（P50／P90／P99、平均降級次數、最長連敗、+10 戰力占比）。建議 +6 失敗不降級。

### 為未來連線化「現在就要做」（Server-Ready，不是現在做伺服器）
P0（晚做就重寫）：**裝備模板與實例分離**、**每件裝備唯一 ID（ULID／UUID）**、核心規則與 UI 分離、存檔 schema 版本化與遷移、強化／掉落／詞綴資料表驅動、**隨機數抽象成 `RandomProvider`**（種子版供離線與測試、未來換伺服器安全隨機；依用途拆 stream：戰鬥、掉落、強化、深淵生成，避免多呼叫一次戰鬥隨機就改變掉落）。
P1：輕量事件紀錄（含 `operationId` 防重複扣料，扣料＋升級＋寫事件要同一次存檔）、資源產出與消耗統計（faucet／sink，做成 Debug Panel）、綁定政策欄位（`bind_on_equip` 等）、規則版本欄位。
不做：交易、帳號、伺服器權威驗證、公會、排行榜、PvP、反作弊。
- **最大架構決策：離線角色與線上角色永遠分離**。離線存檔可被任意修改，唯一 ID、加密、雜湊都擋不住；線上伺服器自己產生裝備。**離線版永遠保留為單人模式**（免費、離線、無內購是玩家下載的理由），線上模式另外發行，兩者可共用劇情、角色、怪物、戰鬥規則、裝備模板、美術與大部分 UI，不共用裝備實例、貨幣、戰力與排行榜。
- 經濟：深淵無限層獎勵不可無限指數成長（51–100 層放緩、101 層以上貨幣趨近上限，增加挑戰與收藏獎勵）；裝備本身也需要 sink（分解、合成、升格）。
- 法規提醒（**ChatGPT 提供，需要你自己查證**）：台灣《網路連線遊戲服務定型化契約》要求付費取得的機會型商品要公開機率，**付費強化材料也可能適用**；Apple 與 Google Play 皆要求付費隨機虛擬物品在購買前揭露機率。建議即使現在不收費，也公開強化、掉落、保底、重鑄機率並保留機率設定版本，不要讓付費貨幣與一般貨幣混在同一餘額。

### ChatGPT 的「現在只做三件事」
1. 資料驅動的裝備系統（`EquipmentTemplate`、`EquipmentInstance`、`AffixDefinition`、`EnhancementConfig`、`LootTable`、`SetBonus`、`SpecialEffect`）。
2. 獨立的遊戲規則核心（`BattleRules`、`EnhancementRules`、`LootRules`、`EconomyRules`、`RandomProvider`、`SaveRepository` 介面）＋存檔 schema 版本。
3. 一個完整、可測試的強化循環（1 把傳說武器、4 條詞綴、+0 到 +10、降級、祝福保底、重鑄）＋跑 10 萬次模擬。

### Claude 評註（題目 3，對照現有程式）
- **已經做到一部分**：核心邏輯在 `src/core/`（battle、cards、dialogue、explore、state、save、`rng.ts`）與 Phaser 場景分離；存檔已有 `version`／`SAVE_VERSION`；`src/core/battle/sim.ts` 已有戰鬥模擬器。ChatGPT 建議的分層我們大致已有。
- **最大缺口：裝備沒有實例。** 現在 `inventory` 是 `Record<物品ID, 數量>`，`members[x].equipment` 只存物品 ID 字串（`weapon/armor/charm` 三格）。有隨機詞綴、強化等級、祝福值就必須改成**每件裝備一個實例物件**，這會影響背包、商店、掉落、存檔遷移、裝備畫面、通關機器人（`autoBuild.ts`）與全部相關測試。**這是長尾系統最大的一次重構，要排在深淵之前做**。
- **亂數還沒集中**：`src/core/rng.ts` 存在，但 `core/dialogue/runner.ts`、`BattleScene`、`CardScene`、`ExploreScene`、音訊仍直接用 `Math.random`。要做到可重現與可模擬，需要逐步改成注入 `RandomProvider`，並拆 stream。
- ChatGPT 提到的 SQLite 對我們不適用：目前是網頁／PWA／Capacitor，存檔在瀏覽器儲存；需要原子寫入時用「先寫暫存再替換」或 IndexedDB 交易即可。
- 我同意**不爆裝、必成安全區、祝福保底、重鑄可保留舊詞綴**；也同意第一版不做玩家自選風險。
- 提醒：Apple／Google／台灣法規那段是它轉述的，我沒有驗證，進入付費階段前要自己查最新版。
- 「保底把強化包裝成世界觀」我建議延續：祝福值叫「星之祝福／星燼凝聚」，避免抽卡手遊觀感。
