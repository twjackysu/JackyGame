# 決策紀錄

> 格式：編號、日期（台北）、決策、理由、替代方案。新的放最上面。

## D-013 2026-10-23 設計定稿，提前開始 M0 核心引擎
- 設計文件 01–10 完成並經兩次獨立審查（第二次含 Python 模擬：燼牌 2000 局、戰鬥 3000 場），矛盾已修正。依規則在 PLAN 標記「設計定稿」。
- 垂直切片 10/29 的時程很緊，所以階段 0 剩餘時間（10/24–25）直接開始 M0（`src/core/` 純邏輯 + 測試）。設計文件之後仍會隨實作微調（記錄在 DECISIONS）。

## D-014 2026-10-23 燼牌「熄燈獎勵」與 P0 縮減
- 模擬顯示 v2 規則下「從不熄燈」最強（54%），放手沒有價值。加入「先熄燈者下一夜多抽 1 張」後降到 38%。P0 只開 6 關鍵字、4 月相；平手夜改為雙方各記 1 勝。

## D-015 2026-10-23 Boss 每輪 2 動 + 全體攻擊；新手 Boss 首戰勝率目標 70–85%
- 模擬發現 3 人隊伍 + 治療下單動 Boss 新手勝率 100%；且「普攻佔 MaxHP 12–18%」與「Boss 有威脅」互相衝突。改由行動次數與全體攻擊製造威脅。

## D-012 2026-10-23 第 1 章隊伍：洛克客座 + 伊歐提早加入
- 設計審查發現第 1 章幾乎單人戰鬥、同伴感薄弱。洛克在酒館後以客座同行到狼王戰；伊歐的霧之湖提前到森林第一站。狼王戰為 3 人隊伍。

## D-011 2026-10-23 序章改為「遠征隊在遺跡中拋下提燈雜役」+ 15 秒冷開場
- 原案「公開職業判定儀式 → 當眾被逐出」與某轉生追放作品的開場骨架過於相近。改用更泛用的「被隊伍拋下」套路；並加入前世遊戲畫面的 5 燈共鳴冷開場，確保前 15 秒就有視覺爽點。
- 最終 Boss 改名「蝕星者 Eclipsar」（原名與既有影集名相同）。

## D-010 2026-10-23 燼牌 v2：五燈座對峙 + 月相（取代三列 + 天象）
- 審查指出 v1 的三列、天象對應、號角、間諜、誘餌、英雄等幾乎是知名卡牌小遊戲換名。保留 Jacky 喜歡的「輪流出牌、熄燈放手、三夜兩勝」精神，核心改成原創：一排 5 燈座、與對面燈座「對峙」燃燒、位置相鄰加成、每夜月相變化。

## D-009 2026-10-23 戰鬥規則補遺與比例減傷
- 星燼：每場從 2 開始、不跨戰鬥；消耗星燼的技能不產生星燼（修掉無限循環）。SP 上限 6、起始 3、輪到自己 +1。倒地與全滅規則、防守判定窗口定義。
- 傷害改為 `× 40/(40+DEF)` 比例減傷；敵人一擊 ≈ MaxHP 12–18%，讓防守輸入真的重要。

## D-008 2026-10-23 Android CI 不使用 android-actions/setup-android
- 該 action 在 ubuntu-latest 上 `sdkmanager` 失敗（Failed to find package 'tools'）。runner 已預裝 Android SDK，直接用 `ANDROID_HOME` 即可，第一次就成功產出 APK。

## D-007 2026-10-23 `latest` 發佈 tag 用 GitHub API 移動
- `gh release edit --target` 不會移動已存在的 tag；改用 `gh api PATCH git/refs/tags/latest force=true`。只動這個 tag，不對分支 force push。

## D-006 2026-10-23 Capacitor 8（而非 7）
- 最新穩定版，支援 Node 22，iOS 預設使用 SPM，Linux 上也能 `cap add ios`，不需 CocoaPods。

## D-005 2026-10-23 TypeScript 5.9.3（不用 7.x）
- 7.x 是新的原生編譯器，生態相容性風險高，這個專案不需要。

## D-004 2026-10-23 遊戲名稱暫定《星燼回響 Echoes of Starfall》
- 原創名稱，世界觀圍繞「墜星留下的星燼」。可在階段 2 前更換。

## D-003 2026-10-23 直式（Portrait）720×1280
- 單手操作、短時段遊玩、對話與卡牌 UI 天生適合直式；手機 RPG 主流慣例。戰鬥做成上敵下我的直式構圖。
- 替代：橫式（戰鬥演出空間較大，但單手不便、對話框佔比高）。

## D-002 2026-10-23 探索採「節點地圖 + 地點熱點」而非自由移動地圖
- 9 天開發期 + 程式美術，自由移動的大地圖（碰撞、tilemap、尋路、美術量）成本過高；節點式在手機上也更好操作，能把資源投入戰鬥演出與劇情。

## D-001 2026-10-23 戰鬥採「回合制 + 時機輸入（點/滑/長按）」
- 符合「簡單但吃技巧」：回合制易懂、時機輸入給高手空間；三種輸入都適合觸控。設定提供「自動時機」照顧輕度玩家。
- 替代：即時 ARPG（觸控虛擬搖桿體驗差、AI 與平衡成本高）、純回合制（缺技巧感）。
